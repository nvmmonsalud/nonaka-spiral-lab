# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

An interactive simulation of Nonaka & Takeuchi's SECI knowledge-creation model extended with "tacit machine knowledge" (AI agents as knowledge carriers). Two halves:

- `web/` — the Next.js app (the only code that builds/runs). Pure client-side: canvas simulation, no backend, no database, no API keys.
- `research/`, `results/`, `artifacts/`, `PLAN.md`, `GROWTH-PLAN.md` — the research corpus the app is grounded in (paper, theory brief, SECI×AI matrix, case studies, standalone HTML presentation). These are markdown deliverables, not code.

## Commands

All development happens in `web/`:

```bash
cd web
npm install
npm run dev        # dev server → http://localhost:3000
npm run lint       # eslint
npm run typecheck  # tsc --noEmit (CI runs this)
npm test           # vitest run — engine + presets (CI runs this)
npm run build      # production build — CI fails fast on compile errors
```

Tests live in `web/tests/` (Vitest, node environment, no DOM). CI (`.github/workflows/ci.yml`) runs lint + typecheck + test + build on PRs and pushes to `main`; `.github/workflows/deploy.yml` then deploys to Vercel production on every push to `main`, so a broken build on `main` blocks deploys. Run all four locally before pushing.

## Next.js version warning

This uses **Next.js 16** (App Router, Turbopack), which has breaking changes vs. training data. Before writing Next.js-specific code, consult the bundled docs at `web/node_modules/next/dist/docs/` (per `web/AGENTS.md`, auto-generated by `next dev` — commit it if it reappears in the diff).

## Architecture

- `web/src/app/` — three routes: `/` (landing), `/simulator`, `/research`. Styling is plain CSS: global design-system tokens and shared classes in `globals.css` (ivory/clay/olive/rust palette as CSS custom properties — reuse these tokens, don't hardcode colors), plus `page.module.css`.
- `web/src/lib/spiral-engine.ts` — pure SECI model: conversion rules (`convertParticle`), per-particle cooldown (`stepParticle`), quadrant geometry (`QUADRANTS`), level stats. No React, no canvas, RNG injectable. Change simulation rules here, with a test in `web/tests/spiral-engine.test.ts`.
- `web/src/lib/sim-config.ts` — pure config codec and the single source of truth for lever bounds (`PARAM_SPECS`: humans/agents are integers 0–12, the other six levers 0–1). Share links (`serializeParams`/`parseParams`) and the versioned JSON file (`exportConfig`/`importConfig`) validate through it, return `{ ok, value | error }` instead of throwing, and reject out-of-range values rather than clamping. Change a bound here, with a test in `web/tests/sim-config*.test.ts`; the head-count sliders and `web/tests/presets.test.ts` read it.
- `web/src/components/SpiralSimulator.tsx` — the canvas/React shell around the engine. A single large `"use client"` component running a `requestAnimationFrame` canvas loop that handles drawing and movement and applies the engine's outcomes. Quadrants sit clockwise S → E → C → I (columns = knowledge converted *to*, rows = converted *from*). Key mechanics:
  - Particles are knowledge units: `kind: "human" | "agent"`, a SECI quadrant (`S/E/C/I`), an ontological `level` 1–4 (individual → group → org → inter-org), and a `corrupted` flag (hallucination = false externalization).
  - Particles advance S → E → C → I → S; a full cycle escalates their level. Agents can also skip articulation via "machine transfer".
  - Simulation parameters (`SimParams`) mirror the ba levers (redundancy, chaos, autonomy) plus feedback rate, machine transfer, and hallucination risk. Live values are kept in refs (`paramsRef` etc.) so the RAF loop reads them without re-rendering; React state mirrors them for the UI. Preserve this ref/state split when modifying the loop.
- `web/src/components/ConfigControls.tsx` — Copy link / Export JSON / Import JSON buttons. Every whole-configuration change (preset button, shared link, imported file) goes through `applyConfig` in `SpiralSimulator.tsx`. The link is read from `window.location.search` in a mount effect on purpose: `useSearchParams` would either fail `next build` (no `Suspense`) or, with one, drop the whole simulator out of the prerendered HTML. Keep `/simulator` as `○ (Static)` in the `next build` route table. These UI paths have no automated test (no DOM framework); when you change them, run the manual browser check in `docs/superpowers/plans/2026-10-11-share-urls-and-json-export.md` (Task 4).
- `web/src/components/SecQuadrant.tsx` — SVG SECI quadrant diagram.
- `web/data/presets.json` — simulator presets (NotCo, Matsushita, siloed org, etc.), each defining initial `SimParams`. Adding a preset means adding an entry here; the `Preset` type is derived from this JSON. Presets are grounded in `research/expansion-research.md` — new presets should cite a real case there. There is a GitHub issue template for preset proposals (`.github/ISSUE_TEMPLATE/simulator-preset.yml`).

## Domain vocabulary

Code and copy use SECI terminology deliberately: Socialization/Externalization/Combination/Internalization quadrants, "ba" (shared context), ontological levels, "false externalization" for hallucination, green = human knowledge / orange = agent knowledge / red = corrupted. Keep new features consistent with this framing — the theory mapping is the point of the project (see `results/theory-brief.md` and `results/paper.md` for the grounding).
